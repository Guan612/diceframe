# 冒险头图链路规范

状态：已实现  
契约版本：1

## 目标

冒险头图不是某个页面的临时背景，而是“内容默认 + 存档选择”的正式数据。世界作者、规则作者和 GM 可以在各自权限范围内提供或修改图片；创建确认页、首页存档卡片和游玩页始终显示同一结果。

## 数据层级

| 层级 | 字段位置 | 用途 | 是否随存档固化 |
| --- | --- | --- | --- |
| 世界默认 | 世界模板 `scene_image` | 具体世界的独立视觉 | 创建或恢复默认时固化 |
| 规则默认 | 规则模板 `scene_image` | 同规则多个世界的共享视觉 | 创建或恢复默认时固化 |
| 内置回退 | 内置规则 ID | 兼容未声明图片的旧内容 | 以稳定 ID 保存 |
| 冒险选择 | 游戏状态 `scene_image` | 当前存档实际使用的图片 | 是 |

默认解析顺序不可由前端自行改写：

```text
世界 scene_image -> 规则 scene_image -> 对应内置规则图 -> freeform_fantasy 兜底
```

## 引用格式

内容包源文件只允许：

```json
{ "kind": "builtin", "id": "freeform_coc" }
{ "kind": "asset", "path": "assets/scenes/manor.webp" }
```

运行时由宿主生成：

```json
{ "kind": "plugin", "plugin_id": "my-pack", "path": "assets/scenes/manor.webp" }
{ "kind": "upload", "asset_id": "<sha256>" }
```

存档 zip 内部临时使用 `save_asset`；导入完成前必须转回 `upload`，不得进入运行中游戏。

## 用户流程

### 创建冒险

1. 用户选择世界和规则。
2. 后端计算内容默认，前端显示实际预览。
3. 用户选择“使用内容默认”或上传专属图。
4. 第三步确认页显示最终选择。
5. 创建时把最终引用写入游戏状态；插件资产先复制到本地图片库。

恢复种子存档默认继承原存档头图；只有用户显式上传时才覆盖。

### GM 后续维护

GM 控台提供“冒险头图”：

- 上传新图：更新当前存档，不修改世界或规则模板。
- 恢复内容默认：按当前世界、当前规则重新解析并固化。
- 切换世界不会静默覆盖 GM 已选图片；GM 可显式恢复新世界默认。

### 内容包制作与分发

制作内容包时可分别指定世界图和规则图。导出器负责：

1. 校验并规范化图片。
2. 写入 `assets/scenes/<sha256>.webp`。
3. 把模板引用改写为 `kind: asset`。
4. 在 manifest 中声明 `scene_images` 和 `content.scene-image`。

内容包安装后以 `plugin` 引用预览；创建游戏时立刻物化为本地 `upload`，保证卸载安全。

### 存档迁移

非内置图片随存档 zip 作为 `scene-image.asset` 导出。导入时重新校验、规范化、哈希去重并写入目标机器的本地图片库，然后把状态改写为 `upload`。

## 图片约束

- 输入格式：PNG、JPEG、WebP。
- 输入上限：8 MB。
- 最小尺寸：320×180。
- 防解压炸弹上限：8192×8192 且不超过 2400 万像素。
- 存储格式：1600×900 WebP，16:9 居中裁切，EXIF 方向已修正。
- 文件名不参与身份计算；规范化内容的 SHA-256 是 `asset_id`，相同图片自动去重。

## 权限与展示

- 全局上传接口仅允许 WebUI 所有者。
- 游戏头图读取允许持有效房间分享身份的玩家。
- 游戏头图修改仅允许该局 GM。
- 受保护图片由前端通过认证请求读取并转换为对象 URL，不把令牌放进 CSS URL。

## 兼容规则

- 旧世界、旧规则和旧存档没有 `scene_image` 时不需要迁移，读取时自动回退。
- 未识别、缺失或越权的图片引用不得直接暴露文件；展示回退图，写操作返回明确错误。
- 内容包不得手写 `upload`、`plugin` 或 `save_asset` 引用。
- 所有页面消费游戏状态或统一解析接口，不维护第二套“按规则猜图”的业务逻辑。
